## 门槛标准与实际修改

原严格模式的数值限额为输入 300000、输出 100000、合计 400000 tokens。预检采用完整请求序列化的 UTF-8 字节及协议余量作为保守输入估算；计入已用、在途预留和未知占用后，超出输入额度或无法分配输出额度就拒绝派发。实际 token 超额也会停止。

按用户明确要求，本地 `.env` 现为：

```dotenv
MODEL_NAME=deepseek-v4-flash-0731
JINDIAO_ENFORCE_TOKEN_BUDGET=false
```

`enforce_token_budget` 从 Settings 固化到 RunPolicy、RunBudget，并写入比较指纹。false 时放开输入/输出/总 token 数值门槛，包括预检、实际用量超额及跨阶段的 token 扣减；仍记录所有用量。默认值和 `.env.example` 仍为 true，HTTP 请求体不能覆盖该服务端设置。

仍保留：300 秒共享超时、64 次模型调用限制、现有工具次数限制、单次默认有界输出 10000、禁止隐式 HTTP 重试、证据/Schema 校验、计量完整性检查。供应商自己的上下文窗口与限额未被绕过。

配置通过 `bin/start.sh` 加载，实际容器已核对 `model_name=deepseek-v4-flash-0731`、`enforce_token_budget=false`，6 个改动模块的安装包与构建源码逐字节一致。`bin/restart.sh` 不会加载新 `.env`，仅用于后续持久化验证。
